How this app is tested

The app is small on purpose. The point is the test suite around it: the same behaviour checked through the browser with Playwright and through the API with Postman.

Playwright API test & Postmancall it directly
  1. The board is only a client. Every click becomes an HTTP call to the REST API: GET to read, POST to create, PATCH to change, DELETE to remove. Open the board and watch the Under the hood panel.
  2. A UI test acts like a user. Playwright opens a real browser, finds buttons and fields by their role and label, and waits by itself until the page is ready. No sleeps.
  3. An API test skips the browser. It sends the request directly and checks the status code, the headers and the JSON, also against the OpenAPI spec. Fast, so it covers many cases.
  4. Combine them. A test creates its data with one API call, then checks the screen. Every test gets its own workspace, so all of them run in parallel.

  • API: CRUD, filters, sorting, auth, workspace isolation, a data-driven table of invalid input, contract checks, response-time budgets.
