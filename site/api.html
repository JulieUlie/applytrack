REST API

The board uses this JSON API, and so can you. Each workspace has its own bearer token, so you can create, break and delete data freely.

Download Postman collection Environment OpenAPI spec

REST in four words

  • GET reads data
  • POST creates something new
  • PATCH changes some fields
  • DELETE removes it

The answer always has a status code: 2xx means it worked, 4xx means the request was wrong, 5xx means the server failed.

Try it

# 1. a workspace with eight example roles
curl -X POST https://applytrack.julietous.workers.dev/api/workspaces \
  -H "content-type: application/json" -d '{"seed": true}'

# 2. send the token from the answer
curl https://applytrack.julietous.workers.dev/api/applications \
  -H "authorization: Bearer at_…"

Or import the Postman collection: it runs all of this in order and checks every answer.

Application fields
FieldRule
companyRequired, at most 80 characters
roleRequired, at most 80 characters
statuswishlist, applied (default), interview, offer, rejected
appliedOnDate YYYY-MM-DD, not in the future
locationAt most 80 characters
linkAn http(s) URL
notesAt most 1000 characters

Example

{
  "company": "Scheldt Systems",
  "role": "QA Test Automation Engineer",
  "status": "interview",
  "appliedOn": "2026-11-06",
  "location": "Antwerp (hybrid)"
}

Read-only: id, createdAt, updatedAt. Unknown fields are rejected, so a typo never gets lost silently.

Error status codes
StatusWhen
400Not valid JSON, or an unknown status or sort
401Missing, malformed, unknown or expired token
404Application or endpoint does not exist
405Method not allowed (see the Allow header)
409Workspace is full (200 applications)
415Body without content-type: application/json
422Validation failed

A validation error

HTTP/1.1 422 Unprocessable Content
{
  "error": "Validation failed",
  "fields": {
    "company": "Required",
    "link": "Must be an http(s) URL"
  }
}

Every answer has an x-request-id header. Workspaces delete themselves after 30 days.
